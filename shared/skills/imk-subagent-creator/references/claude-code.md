## 配置と優先順位

| 場所 | スコープ | 優先順位 |
|---|---|---|
| 管理設定内の `.claude/agents/` | 組織 | 1（最高） |
| `--agents` の JSON | 現在のセッション | 2 |
| `.claude/agents/` | プロジェクト | 3 |
| `~/.claude/agents/` | ユーザー | 4 |
| プラグインの `agents/` | プラグイン利用範囲 | 5 |

- プロジェクトでは現在の作業ディレクトリからリポジトリルートまでを走査し、
  同名なら作業ディレクトリに近い定義が優先される
- プロジェクト / ユーザーの `agents/` は再帰走査される。サブディレクトリは整理用で、
  エージェントの識別子には影響しない
- 同じ階層内で同じ `name` が複数ある場合、どれが選ばれるかは保証されない。
  名前を一意にし、`/doctor` で重複を調べる
- 既存の `agents/` ディレクトリへの追加・編集は数秒で再読込される。
  セッション開始後に初めて `agents/` ディレクトリを作った場合は再起動が必要

## ファイル形式

YAML frontmatter + Markdown 本文。本文がサブエージェントの system prompt になる。

```markdown
---
name: code-reviewer
description: コード変更後に品質・正しさ・セキュリティをレビューする
tools: Read, Glob, Grep
model: inherit
---

変更箇所を証拠に基づいてレビューし、重要度順に指摘を返す。
```

`name` と `description` が必須。ファイル名は識別子ではないが、管理しやすいよう
`<name>.md` に合わせる。

## フロントマター

| フィールド | 必須 | 意味 |
|---|---:|---|
| `name` | Yes | 英小文字とハイフンの一意な識別子 |
| `description` | Yes | Claude がいつ委譲するかの判断材料 |
| `tools` | No | 許可するツール。省略時は利用可能なツールを継承 |
| `disallowedTools` | No | 継承または `tools` から除外するツール |
| `model` | No | `inherit`、モデルエイリアス、完全なモデル ID |
| `permissionMode` | No | `default` / `manual` / `acceptEdits` / `auto` / `dontAsk` / `bypassPermissions` / `plan` |
| `maxTurns` | No | エージェントの最大ターン数 |
| `skills` | No | 起動時に本文を事前読込するスキル名の配列 |
| `mcpServers` | No | 既存サーバー名またはインライン MCP 設定 |
| `hooks` | No | このサブエージェント内だけで動く hooks |
| `memory` | No | `user` / `project` / `local` の永続メモリ |
| `background` | No | `true` なら常にバックグラウンド実行 |
| `effort` | No | モデルが対応する推論量 |
| `isolation` | No | `worktree` で一時 git worktree に隔離 |
| `color` | No | UI 表示色 |
| `initialPrompt` | No | `--agent` 等でメインエージェントとして起動した際の初回入力 |

`manual` は `default` の別名。必要なフィールドだけを書く。`bypassPermissions` は確認を飛ばすため、ユーザーが明示的に
必要性を判断した場合以外は使わない。プラグイン提供エージェントでは `hooks` /
`mcpServers` / `permissionMode` が無視される。

## モデルと権限

`model` を省略すると `inherit`。モデルはおおむね次の優先順位で決まる。

1. `CLAUDE_CODE_SUBAGENT_MODEL`
2. 起動時の指定
3. 定義ファイルの `model`
4. 親会話のモデル

組織のモデル許可リストに無い指定はスキップされ、継承モデルへフォールバックする。
固定モデルを要求する場合は、実行時の表示でも確認する。

読み取り専用にしたい場合、`tools: Read, Glob, Grep` のような allowlist が明確。
`Bash` は読み取りコマンドだけに限定できないため、含めるなら hooks や sandbox も検討する。
`tools` と `disallowedTools` の両方がある場合は、拒否を適用してから許可リストを解決する。

サブエージェントが使えないツールや、バックグラウンド時に削られるツールがある。
定義に書いたツール名が 1 つも解決できない場合、起動に失敗するため実地確認する。

## コンテキストと実行

- 通常のサブエージェントは独立した新しいコンテキストで始まり、親の会話履歴や
  親が読んだファイルをそのままは受け取らない
- 親が委譲メッセージにタスク固有の文脈をまとめる
- カスタムサブエージェントは自身の prompt、環境情報、適用される CLAUDE.md、
  親セッション開始時の git status、`skills` で指定したスキルを受け取る
- `isolation: worktree` を使わない場合、親と同じ作業ツリーで動く。並列書き込みは
  競合しうるため、役割と対象ファイルを分離する
- `background: true` は実行方法を固定するが、親が結果を直ちに必要とする役割には向かない

## 呼び出しと検証

呼び出し方:

- 自然言語で名前を指定する
- `@` メンションで対象エージェントを確実に指定する
- `claude --agent <name>` でその定義をメインセッションとして使う

自動委譲は依頼内容・`description`・現在の文脈で判断される。自動利用を期待する場合は
`description` に具体的な対象とタイミングを書く。

検証では、明示起動 → 権限 / モデル / 出力確認 → 自動委譲の順に試す。
定義が見えなければ、配置、`name` 重複、新規 `agents/` ディレクトリ作成後の再起動を確認する。
