# ADR-0018: サブエージェント定義作成支援を 4 本目の共有スキルとして追加する

- ステータス: 承認済み
- 日付: 2026-07-28

## コンテキスト

Claude Code / Codex / Cursor はいずれも、独立コンテキストで専門タスクを処理する
カスタムサブエージェントを定義できるようになった。しかし成果物の形式は統一されていない。

- Claude Code は `.claude/agents/*.md` の YAML frontmatter + Markdown
- Codex は `.codex/agents/*.toml` の TOML
- Cursor は `.cursor/agents/*.md` の YAML frontmatter + Markdown
- 読み取り専用やバックグラウンド実行など、同じ意図のフィールド名も異なる
- Cursor は Claude Code / Codex の互換配置も走査するため、同名定義の優先順位まで
  理解しないと意図しないファイルが選ばれる

3 ツールとも比較的新しい機能で変更が続いており、学習知識から類推すると、
別ツールのフィールド混入、古い配置方法、存在しない設定の生成が起きやすい。
これは hooks 作成支援で解決した「似た概念だがネイティブ形式が違う成果物」の問題と同型である。

一方、サブエージェントの実行そのものと、再利用する定義ファイルの作成は別の依頼である。
単に今回の作業を並列委譲したいだけのときまで creator スキルを発火させると過剰になる。

## 決定

**ユーザースコープに展開する共有スキルへ imk-subagent-creator を追加し、4 本とする。**
ADR-0017 の「3 本」は本 ADR により「4 本」に置換する。

1. **3 ツールの仕様ダイジェストを同梱する**
   - `references/claude-code.md`
   - `references/codex.md`
   - `references/cursor.md`
   - 各資料に調査日と公式一次情報 URL を記録する
2. **共通契約からネイティブ形式へ変換する手順を定める**
   - 名前、委譲条件、責務、非責務、完了条件、返却形式を共通設計する
   - その後、ツール別テンプレートで Markdown / TOML へ変換する
   - 全ツール対象では単一ファイルへの無理な共通化を行わず、3 つのネイティブ定義を作る
3. **3 種のテンプレートを同梱する**
   - Claude Code 用 Markdown
   - Codex 用 TOML
   - Cursor 用 Markdown
4. **機械検査スクリプトを同梱する**
   `validate-agent.sh` が必須フィールド、本文、命名、代表的な別ツールフィールドの混入を検査する
5. **実地テストを必須手順にする**
   静的検査の後、明示起動で発見・実効モデル・権限・返却形式を確認し、
   必要な場合だけ自動委譲と near-miss を試す
6. **発火範囲を定義ファイルの作成・修正に限定する**
   単発のサブエージェント委譲では発火させないことを description に明記する
7. **harness-check の標準提案項目には追加しない**
   サブエージェントはプロジェクト立ち上げ時の基礎要素ではなく、繰り返す専門役が
   明らかになってから導入する。必要になった時点の明示依頼を creator が扱う

## 検討した代替案

- **imk-skill-creator に含める** — スキルは親コンテキストで再利用する手順、
  サブエージェントは独立コンテキストで動く役割定義であり、成果物・発火語彙・検証方法が異なる
- **Claude Code 形式を共通原本にする** — Codex は TOML と
  `developer_instructions` を必要とし、単一ファイルでは成立しない
- **Cursor の互換走査だけに頼る** — Claude Code / Codex 固有設定を Cursor が
  同じ意味で扱う保証がなく、同名定義の選択も曖昧になる
- **参照資料だけを docs に置く** — docs は採用プロジェクトへ展開されず、
  実際に定義を作るエージェントから見えない
- **harness-check のチェックリストに追加する** — 具体的な繰り返し役割が無い段階で
  汎用エージェントを量産し、ユーザースコープを最小限に保つ方針と衝突する

## 結果

- ハーネスの実体は「共有スキル 4 本 + ユーザー常駐指示の配布装置 +
  settings の初期配置」になる
- サブエージェント定義を、各ツールの現在のネイティブ仕様に沿って作成・検証できる
- ツール別ファイルに共通の役割説明が重複する。形式差の吸収に必要な重複として認め、
  変更時は共通契約から全対象ファイルを更新する
- 参照資料は陳腐化しうるため、食い違い発見時に一次情報と references の両方を更新する
